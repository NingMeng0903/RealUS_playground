Frozen continuous-GT / finite-public-prior mismatch screen, 2026-11-10

Scope and claim boundary
------------------------
This is a bounded offline L0 geometric mismatch screen.  It reuses the
existing planning ``run_episode`` implementation, public stop verifier,
wall-clock charging, capability scene, and observation model.  It does not
modify the observation, planning, capability, controller, production, or
hardware files.  The result is only a finite 32-point belief versus eight
independently generated continuous ground-truth worlds diagnostic.  It must
not be described as calibrated continuous SMC, a clinical/sensor result, or a
generalization guarantee.

Read-only sources
-----------------
The runner imports the existing ``planning.system.run_episode`` and the
``planning.run_experiment.contexts`` helper.  ``observation.environment``,
``planning/system.py``, ``planning/PROTOCOL.json``, and the capability scene
files are read-only inputs and are hashed in the result.  The policy receives
only the public finite prior and public scene/robot state.  A selected GT
world, its index, its hash, nearest-prior comparison, and audit geometry are
never passed to ``Planner`` or used to construct candidates, likelihoods,
weights, or rewards.

Frozen populations and conditions
----------------------------------
Public model prior: ``env.sample_prior(seed=720502, n=32)``.  The eight
private GT worlds are independently generated by
``env.sample_worlds(seed=720380, n=8, split='test')``.  The split argument is
recorded exactly as supplied; the GT list is separate objects from the public
prior and is never used as candidate support.

There are two private-world conditions, each using the same eight object
indices so that the comparison is paired:

  iid: the private worlds returned by ``sample_worlds`` unchanged;
  shifted: copy each private world, add +0.008 m to its common
  ``registration[1]`` (both sources), and add +0.4 to each source's
  ``modes[:,1]`` before rebuilding points through ``env._world``.  Because
  ``_points`` multiplies this mode by 0.25, this is a +0.10 slope term in the
  declared geometry.  Nuisance controls/depths/identity/detectability remain
  copied unchanged.

The shifted GT is an audit-only private world.  It is not appended to the
prior, not exposed to the planner, and not used to choose actions.  For every
GT/condition, the runner computes the nearest public-prior geometry RMS
``sqrt(mean((gt.points-prior.points)**2))`` for audit reporting only, with the
nearest prior index kept outside policy inputs.

Episodes, methods, and resource rules
--------------------------------------
Run exactly 8 objects x 2 conditions x 2 methods = 32 episodes, all in the
single public ``a0_identity`` context.  The methods are:

  A_continuous_servo: passed to the existing planner unchanged;
  B_two_step: passed to the existing planner unchanged.  This is the
              planner's sampled two-step full-belief branch, including
              public-block posterior/future planning.  It is not the separate
              ``fixed_two`` precommitted-second-action branch.

Each episode constructs a fresh ``Robot`` cache for its object/condition and
method.  The runner asserts that the returned episode method equals the
requested method before adding audit metadata; a no-GT stub contract check
also verifies the two method labels are passed through unchanged.  Method
order is rotated deterministically by one master
``np.random.default_rng(720531)`` over the 16 object/condition cases; the
chosen order is recorded.  The existing ``run_episode`` is called with
``max_actions=6`` and its fixed 60 s deadline.  Its public five-frame stop,
0.5 s hold, model-based planning, static endpoint checks, motion estimate,
and compute wall charging are unchanged.  No seed or planner parameter is
retuned.

Common-random-number renderer key
----------------------------------
The private renderer key is exactly
``('continuous_mismatch', condition, object_index, 'a0_identity')`` and does
not contain the method label.  Therefore, when paired methods take the same
actual pose at the same action ordinal for the same object/condition, their
rendered observation noise is shared.  Different actual poses may receive
different noise, as required by the actor key; GT world identity and nuisance
variables remain persistent across all actions in that episode.

Failure and anomaly handling
-----------------------------
Every scheduled episode remains in the output.  Exceptions, incompatible
public evidence, endpoint failures, non-finite numeric values, or other
numeric anomalies are retained with status/failure detail and assigned
``rmt_s=60.0``; no sample is silently dropped.  Successful rows preserve
the full event list returned by ``run_episode`` including public frames,
audit-only frames, posterior vectors, decisions, endpoint/motion/compute
times, and all query counts.

Mismatch diagnostics
--------------------
For each event, derive and save from the returned finite-catalogue weights:

  raw_ess = 1/sum(w**2),
  posterior_max_weight = max(w),
  unique_effective_support = count(w > 1e-12).

The pre-update ``prior_before`` ESS is also saved.  These are finite-prior
diagnostics and warning signals only; they do not establish continuous
posterior coverage or SMC calibration.  Row summaries include minima/maxima
and a mismatch-warning flag without changing policy execution.

Public/private hashes and paired summaries
-------------------------------------------
The public-prior digest is exposed as ``public_prior_sha256``.  Private GT
digests are written only inside the ``audit_private`` section, never in
public event/policy fields.  Results include all 32 rows, public-prior and
source hashes, method order, audit-only nearest-prior RMS values, full
events, and summaries by condition/method.  Paired cluster summaries join
the two conditions within each object and method, reporting signed shifted
minus iid deltas for RMT, success/false-stop, actions, and geometry RMS.

Artifacts
---------
The runner writes only in this directory: ``RESULTS.json`` (incremental and
final), ``RESULTS.sha256``, and ``REPORT.txt``.  It does not run the workload
at import time; an explicit output directory and release invocation are
required.  The protocol is frozen before any formal strategy episodes.
