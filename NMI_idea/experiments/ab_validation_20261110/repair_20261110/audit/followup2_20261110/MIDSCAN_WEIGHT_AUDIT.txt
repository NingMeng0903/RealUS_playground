Independent mid-scan / QP1 weighting audit, 2026-11-10

Verdict
The four weight-ablation and six relaxed-reference saved runs support the reported middle-scan pose accuracy. The user's changed acceptance emphasis is applied exactly as documented in MIDSCAN_EVALUATION_PROTOCOL.txt: this is a post-run user-directed metric clarification, not an original preregistration. It does not waive mechanical limits. No native process, hardware, or experiment rerun was performed for this audit.

Independent checks
Every saved joint state was passed through the URDF tcp FK. Position error and geodesic orientation error were independently recomputed from the 4x4 poses. Desired arc fraction and perpendicular error were reconstructed by projecting onto the original 17-pose polyline. All-motion, phase [.8,duration-.8], arc [.2,.8], and all ten non-settle arc deciles agree with the root's summary, including sample counts and gates. Every trace SHA agrees with its result. The four weight-case raw result, reference and native-config SHAs also agree. Paired desired poses and clocks are bit-identical; the complete native dumps differ only in qp.task_weight. Continuous acceleration/jerk were recomputed from the saved entry velocity/acceleration and every command.

Important interpretation
The baseline's 0.30 mm along-track number describes the frame of maximum total error; it is not the whole-run along-track maximum, which is about 6.04 mm for path0. A fixed reference and identical seeds show a causal task-weight effect on these runs. This does not establish optimal weights, universal performance, or exclusion of solver conditioning effects. QP1 mixes linear m/s and angular rad/s residuals, and its weights set how unavoidable residual is distributed. QP2 locks the achieved QP1 task, so these records do not support direct secondary overwriting as the explanation.

W-only keeps the 6-degree lead envelope. The resulting worst command jerk is about 509.7 / 481.1 rad/s^3 at a collapsed -0.777807 rad/s box, compared with the unchanged 300 limit. These are substantive failures, not rounding. The 20-degree plus both-end .8-second cases retain much smaller negative jerk margins, also strict FAIL. The phase/middle pose success must never be reported as complete mechanical or physical execution success.

Production configuration recommendation (not implemented by this audit)
Use an optional explicit inner.qp.task_units mode in the shared Python config resolver. When absent, preserve the legacy task_weight behavior. Resolve it once to the existing six effective task_weight entries before constructing either Python or native QP; log both source scales and final weights in the native dump. Do not normalize again in the reference, outer-loop error, Jacobian, command, or native solver.
A transparent compatible schema is linear_scale_m=.002, angular_scale_rad=pi/90, angular_cost_weight=50, which yields W_linear=50*(angular_scale_rad/linear_scale_m)^2=15230.870989335432 and W_angular=50. Equivalently cost scale k=50*(pi/90)^2 multiplies ||v_linear/.002||^2+||omega/(pi/90)||^2. Require finite strictly positive scales and weights, and reject ambiguous simultaneous explicit legacy weights and enabled unit-scale settings rather than silently double-applying them. A profile may choose one representation explicitly.
These spatial scales define relative QP1 task residual priorities. They do not change physical units of the signals, do not enforce a 2 mm/2 degree pose constraint, and are not uniquely determined by dimensional analysis. Distinct position/orientation outer-loop gains further mean this is not exactly equal normalized pose-error cost. Keep q/v/a/j, lead, collision, and solver admission limits in their existing separate fields and checks. Retain the tested absolute cost scale: arbitrarily rescaling all six weights is not generally equivalent because QP1 also contains 1e-8 joint regularization and potentially CBF slack cost, and numerical conditioning changes. Test parser/native export parity and invalid config rejection. No hardware default deployment follows from these offline results.

Evidence: check_midscan_weights.py, midscan_weights_independent.json/.log. The json contains all 130 window summaries, FK errors, source trace hashes, exact peak coordinates and strict derivative margins.
