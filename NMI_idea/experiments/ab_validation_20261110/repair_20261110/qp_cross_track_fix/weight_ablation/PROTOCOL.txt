Frozen paired native-QP task-weight diagnostic, 2026-11-10

Scope
------
This is an offline, motion-only diagnostic for the 8.57 mm cross-path error.
It uses the existing repaired native replay bridge and the specified Genesis
interpreter.  There is no robot/session binding, hardware I/O, production
source edit, default change, limit/gain/ramp change, or retuning claim.

Frozen input and paths
----------------------
Input is repair_20261110/audit/phase2_native_subset_inputs.npz.  Use exactly
branch4_path0_T with branch4_path0_q_seed and branch4_path1_T with
branch4_path1_q_seed.  Each path is run exactly once under each of the two
weight cases below (four native replays total), in this order:

  path0_baseline, path0_tolerance_unit, path1_baseline, path1_tolerance_unit

No failed case is rerun.  The two paths retain their frozen 17-pose geometry
and seed; no waypoint, branch, seed, or input selection is changed.

Reference and timing contract
-----------------------------
Both cases use the full six-dimensional analytic reference already used by
qp_reference_followup/run_reference_protocol.py: the same polyline pose and
Slerp orientation, world-frame angular feed-forward, speed 0.02 m/s, existing
soft-start ramp 0.4 s, and 2.0 s endpoint settle.  The reference construction
is not a controller retune.  The Cartesian outer loop, native QP, deterministic
model clock, URDF TCP, ideal q feedback, and all existing defaults remain as
implemented by repair_20261110/dird/qp_replay.py.  Whole-motion duration is
reported from every saved trace, including any early stop.

Only task weights differ
------------------------
Before each controller is built, set only the in-memory
bridge.raw['inner']['qp']['task_weight'] field:

  baseline:       [100, 100, 100, 50, 50, 50]
  tolerance-unit: [W,   W,   W,   50, 50, 50]

where W = 50*(radians(2)/0.002)^2 = 15230.870989335432 (float64).  This is a
metres/radians unit conversion comparison only; it is not claimed to be a
theoretically optimal weight.  No other raw field is changed.  The runner
records the parsed cfg.qp.task_weight and the actual line in the temporary
native wbc.cfg dump, then preserves that dump text/hash in this directory.

Gates and reporting
-------------------
Use the existing strict gates without relaxation: full-run max position <=
2 mm and max orientation <= 2 degrees; mechanical q/velocity/acceleration/
jerk margins must each remain >= 0, sampled self-collision distance >= 10 mm,
no solver fault, and no replay failure.  Negative margins and signed error
components are retained and reported; tiny negative numerical values are not
rounded into a pass.  Cross-path reporting decomposes actual-minus-desired
translation against the local frozen path tangent into signed along-track
error and a vector cross-track/normal residual (its norm plus signed Cartesian
components).  Rotation is reported as the existing error norm and signed
rotation-vector components.  Path and full-motion p95/max values are both
reported.

Same-reference sensitivity
--------------------------
The baseline and tolerance-unit runs use identical reference geometry/time
law.  Any trajectory difference is therefore a native QP task-weight,
conditioning, or numerical-solver effect, not a reference change.  The
runner saves reference samples and reports shared-tick output differences;
it does not infer optimality or retry a sensitive/failing case.

Artifacts
---------
run_weight_ablation.py is the sole runner.  RESULTS.json contains one raw
record per case, with per-case raw JSON, trace, reference, and native-dump
SHA256 values.  REPORT.txt is generated after the four one-shot runs and
includes the signed cross/along/rotation summaries, strict gates, durations,
and same-reference sensitivity.  No artifact is a hardware validation claim.
