# Phantom 8DOF 曲面扫描

在仓库根目录、`rm75` 环境中运行。已有的窗口 A 需要重启一次：

```bash
python -m peirastic.apps.run_controller --log-csv
```

Orbbec 发布器在 `camera_calib` 环境中另开窗口。此次更新包含数值库线程限制，已有的发布器也需要退出后重启；Genesis 窗口同样需要重启才能应用核心分配和线程限制：

```bash
python perception/apps/run_orbbec_cloud_publisher.py
```

扫描窗口：

```bash
python -m peirastic.DEMO.phathom_scanning.s_scan
```

不传参数默认为矩形往返直线扫描。切换双叶李萨如轨迹：

```bash
python -m peirastic.DEMO.phathom_scanning.s_scan --pattern lissajous
```

需要慢速进入悬停点时，两条命令均可加 `--ptp-v 0.10`。

两种模式默认共用 **140 × 80 mm** 区域，中心取 phantom 外接矩形中心，长方向沿其长边，左右及近远两侧对称。用 `--scan-length-m 0.14 --scan-width-m 0.08` 显式指定尺寸；这两个量是 phantom 基准平面上的投影尺寸，曲面上的实际路程可能稍长。每次检测更新区域的空间位置和法线，保持指定长宽。区域加探头占地和边缘余量无法放入实测上表面时会拒绝规划，不自动缩小或移动区域。

启动后设为 8DOF，MOVEJ 到现有 `phathom_detect_pose.json` 保存的检测姿态（轨道约 533.3 mm，与此前已验证正确的 MOVEJ 相同）。

1. 第一次回车：获取静止状态下的点云，检测 phantom 上表面，用轮廓的最小面积外接矩形确定中心和长边。直线模式各行平行长边，沿短边从近侧逐行向远侧推进，方向交替；李萨如模式在同一居中区域内走一个闭合双叶曲线。两者逐点投影到实测曲面，并用局部法线引导姿态。终端打印尺寸、起点、法向、悬停目标和预览文件路径。
2. 第二次回车：调用与 `DEMO.cartesian` 相同的 `arm.cartesian(..., block=1)`，即目标 IK + 8DOF 关节 PTP，到扫描起点沿该点的局部外法向 40 mm 处。到位需满足位置 2 mm、旋转 2°；关节 PTP 的中间 TCP 路径不保证直线。
3. 第三次回车：只启动一次 `hfpc(..., wait_for_contact=True)`，进入工具 Z 力控、其余轴位置控制的笛卡尔混合轨迹模式。默认 4 N，由现有力控先以最多 12 mm/s 自动寻找接触；参考固定在原规划首点，前馈为零。控制器自身确认接触后开始推进同一条轨迹，保留同一个力控对象、接触状态和积分状态。接触超时或超出检测表面下方 10 mm 会停止。

接触时实测 TCP 与原规划起点可以有偏差。工具 X/Y 的位置闭环负责收敛切向偏差，工具 Z 继续由力控处理，姿态跟随规划参考；不会把整条轨迹平移到接触点。扫描时长从确认接触之后计算，并跟随控制器 governor 的参考时间。日志的 `t_ref` 是实际轨迹进度，`contact` 来自力控制器，`vz_cmd` 是工具 Z 速度指令（mm/s），不是实测速度。

本次衔接修复需要重启窗口 A。旧脚本用 `abs(Fz)` 将日志中的 −1.20 N 当成接触，随后第二次启动 HFPC 又清空力控状态。现在脚本不再自行判定接触，也不额外等待力稳定到 4 N。既有正目标力约定下，持续负 Fz 不能确认首次接触；首次确认后，后续丢接触仍由原力控处理，不重新初始化扫描参考。

目前脚本的 12 mm/s Z 上限同时约束下探和回退，因此它不是无限速的手拖动模式。相同参数离线输入 +10 N 时，力控请求沿 −tool Z 回退；持续 −10 N 时，现有接触检测会转为脱离并重新下探。仅凭一秒一次的 Fz 日志，不能确定某次手推的实际速度响应；需要结合 `contact`、`vz_cmd` 和 CSV 中的实测速度分析。

扫完核对终点，切换位置轨迹控制，从**实测 TCP** 沿 `−tool Z` 抬起 10 mm，然后 MOVEJ 回到同一个检测姿态。这里 `+tool Z` 指向 phantom 内部，因此退出方向是 `−tool Z`。

默认探头宽 50 mm，内缩边界采用工具 XY 平面的 50×50 mm 方形占地假设，按规划姿态投影后的实际方形方向计算边距；目标行距不超过 40 mm（至少 20% 名义重叠），边缘额外留 10 mm。覆盖取决于有效点云支持和探头真实接触形状。每个轨迹点的位置和法线来自局部加权二次曲面拟合（默认半径 30 mm，`--surface-radius-m`），工具 `+Z` 朝向该点的局部内法线。

直线模式在指定的居中矩形中布置等长行，换行沿短边移动。李萨如与它共用区域长宽，不因曲线少到达角部而扩大范围；两种模式的采样分布不同。

姿态以检测时的完整实测工具旋转为起点，每步仅做对齐下一点内法线所需的最小倾斜，并连续传递工具 X/Y 方向。参考姿态的相邻旋转向量在工具 Z 上的分量为零；S 换行不带动探头掉头，也不为了平行长边而强行旋转探头。曲面上的世界 Euler yaw 可能随倾斜变化，它不同于绕工具 Z 的自转。控制器插值位置和姿态。平均平面法线仅用于建立扫描二维坐标，并非强制世界竖直或整条轨迹固定姿态。悬停仍是上述关节 PTP，其关节插值过程的瞬时工具旋转不由扫描参考姿态保证。

投影必须在实测三角形支持内；三角形允许跨度先按全局采样间距判断，超过时结合局部二维三角网间距、查询点四周采样分布和拟合质量判断，始终保留 30 mm 上限。支持判断还检查局部拟合点数、分布和残差。真正的深度大缺口、凸包外或拟合失败会拒绝规划，不使用原先单一的 12 mm 最近点门限。

每次检测保存到 `peirastic/logs/phantom/<时间>/`：

- `preview.png`：上表面、所选轨迹及悬停点；坐标原点为 phantom 中心，无需启动 Genesis。
- `plan.json`：控制器坐标系下的位姿、法向和规划参数。
- `cloud_and_plan.npz`：相机原始点、RGB、检测时 q8、转换后的点和规划结果。
- `capture.npz`：规划前即保存原始输入，失败也保留；失败时另外输出 `failure.json`、`failure.png` 和已识别的上表面。
- `force_trace.csv`：开启 HFPC 到结束期间的力记录，包含时间、补偿后的工具坐标系 Fx/Fy/Fz、力矩、目标 Fz、接触阶段与有效性标记。
- `force_trace.png`：结束后自动生成的力曲线及目标力对照；绘图放在抬升和返程之后，中途停止也保存已有数据。
- `force_trace_summary.json`：采样统计与完成/中止状态。
- `motion_trace.csv`：扫描窗口约 20 Hz 记录的接触阶段、下探指令、实测 TCP 位姿、q8、表面间距及 QP slack。`vz_pose_diff_mm_s` 是相邻位姿差分在当前工具 Z 上的速度估计，与 `vz_cmd_mm_s` 的外环请求分开，不能代替控制器原始速度反馈。用于排查“请求下探但实机悬停”。

力记录由扫描窗口以 100 Hz 轮询现有控制器力发布通道，CSV 边采边写；它是独立采样记录，不保证保留控制器全部 200 Hz 周期。失效或陈旧数据保留缺失标记。若只能取得控制面板 Fz，其他力分量会记为缺失并标注来源，不补零；窗口 A 的 `--log-csv` 仍可用于诊断每个控制周期。

启用 HFPC 前会打印力 CSV 和结束后力图的完整路径；图片保存到磁盘，不自动弹窗。

QP 拒绝发布时，窗口 A 现在先执行停止，再自动保存 `rm75_control/apps/logs/peirastic/faults/*.json`，终端打印具体路径。文件包含该次求解状态、速度约束、实测/命令关节位置及位置边距。`rail(lo=0,hi=0)` 在辨识中是锁定地轨速度，不单独表示位置越界；本次辨识故障的判断和证据限制见 [辨识排查记录](../../../MD/identify_publication_20260908/evidence.md)。

只检测/保存预览，不发送任何运动命令：

```bash
python -m peirastic.DEMO.phathom_scanning.s_scan --dry-run
```

从保存的输入离线重放检测/规划，不附着控制器：

```bash
python -m peirastic.DEMO.phathom_scanning.s_scan --replay <目录>/capture.npz
```

`preview.png` 的二维横轴沿 phantom 长边，纵轴沿短边；虚线为拟合外接矩形，浅蓝色方形为实际工具姿态下的占地投影。三维紫色箭头为逐点局部外法线，橙色箭头为工具 X 方向。`plan.json` 保存每点法线、位姿、长边方向以及曲面拟合和工具旋转诊断。

需要更慢的悬停 PTP 时显式传入 `--ptp-v 0.10`；扫描速度用 `--speed-m-s 0.018`。前者是关节 PTP 速度比例，后者单位为 m/s。

## 2026-09-08 定位结果

点云旧代码使用 `param_model` 的 Genesis generated URDF，而控制器使用 `model.DEFAULT_URDF`。前者多出 `rail_mount=20 mm` 和滑台高度 `256 mm`。同一组 q8 下，FK 的旋转一致，位置差为 `(0, 0, +276 mm)`；虽然根节点都叫 `rail_base`，其原点不同。现统一用控制器 URDF 转换点云，未硬编码减去某个高度。

`run_20260908_034408.csv` 中，悬停前实测 TCP Z 约 399.9 mm，旧目标 Z 为 484.475 mm，所以机器人向上追踪。修正相同点云目标应为约 208.475 mm。离线 IK 已验证修正后的目标可达。

另外两处实际错误也已修正：S 扫描的悬停步骤此前调用了 `cartesian_track`；非 pad 的 `TRACK_HYBRID` 编译没有保留调用方 label，导致脚本一直等待 `phathom_s_close`，而控制器发布的是 `track_hybrid`。全局折线参考现在到达末端后将前馈速度置零。

故障日志需分别理解：

- `native_timeout`：同一 native 请求等待从 20 ms 延长到约 51.5 ms，达到请求年龄停止阈值。上一次约 3.3 ms 求解时间不能代表本次等待期间的求解时间；现有日志不能区分调度延迟与求解长尾。
- `FA24 latched without encoder` 后跟 `modbus error (3x): not connected`：轨道编码器/Modbus 反馈链异常，HOLD 会清零 FA24。这与点云坐标错误是不同问题。
- `run_20260908_032609.csv` 第 4618 行的 `publication_infeasible`：QP1 报 `primal_infeasible`，QP2 未运行；当次求解约 2.87 ms，并非 timeout。现有名称未准确表达失败来源，日志也不足以确定是哪一对 CBF 约束冲突。

Genesis 是独立的只读状态镜像，未发现 SHM 损坏证据。资源争用是否加重超时，需要控制器单独运行与开启 Genesis 的同条件对照；本次没有改大超时阈值或绕过约束。

后续 `native_timeout` 资源排查及修复见 [稳定性记录](../../../MD/native_timeout_stability_20260908.md)。默认控制线程使用 CPU 2，native 使用 CPU 4；相机和 Genesis 避开这两个物理核心及其 SMT 线程。更新后同时重启相机、控制器与 Genesis。

本次验证为离线 FK/IK、几何及模拟客户端流程测试，没有启动实机运动，实际接触和扫描仍需设备验证。

## 2026-09-08 上表面截断与曲面法线修复

`nearest in-plane distance=0.014 m, limit=0.012 m` 发生在检测之后的轨迹规划，表示查询附近没有满足旧固定半径的点，并非机器人越过某个工作空间位置限制。

后续只读采集的一帧显示：桌面估计 Z 为 7.46 mm，棕色 phantom 点 Z 为 163–179 mm。旧的 `height_max_m=0.16` 只留下 937 个棕色点中的 138 个低边点；浅色纹理又被颜色筛选排除，产生人为点云缺口。这帧的机器人姿态与用户贴出的失败时姿态不同，因此它验证了截断机制，不能替代原始失败帧。

现取消默认 16 cm 高度上限，用颜色定位、实测邻近几何补回浅色表面点；局部上表面延续保留真实曲率，避免只取平面 ±8 mm 薄片。该帧恢复 1820 个上表面点，范围约 176×118 mm，Z 跨度 15.9 mm，并成功生成 S 轨迹。逐点局部法线相对平均法线最大变化约 9.4°。悬停、接触检查和终点检查均使用相应轨迹点的局部法线。

## 2026-09-08 长边方向、工具自转与采样误拒绝

`20260908_051548_662477` 已识别出 2256 个上表面点。该次失败发生在局部投影阶段：查询处三角形最长边约 11.865 mm，旧的全局最近点间距推算门限约 11.682 mm，仅差 0.183 mm。局部实际有 190 个拟合点，残差约 0.91 mm；现用上述局部二维支持补充判断，保留真实缺口拒绝检查。

此前扫描轴由机器人朝向确定，会相对 phantom 长边斜扫。现通过轮廓几何确定长边，机器人朝向只用于选择近侧和扫描符号。此前逐点使用同一 yaw 提示向量重新构造姿态，无法严格保证工具 Z 无自转；现使用从实测工具姿态出发的最小旋转传递。该失败上表面的实测点和姿态已纳入离线回归测试。

该原始 `capture.npz` 修复后离线回放成功：轮廓长短边约 230.8×176.4 mm，中心线矩形约 148.9×89.7 mm，4 行、89 个位姿，行距 29.9 mm。参考姿态逐段工具 Z 自转分量在数值精度内为零；局部法线相对参考面最大倾斜约 14.0°。58 项相关测试通过，包括实测失败点云、等长平行扫描行、无斜向换行、旋转后的探头边距及真实大缺口拒绝。未执行实机 PTP 或接触扫描验证。

## PTP 到位后的 publication_infeasible

`20260908_054226_368190` 的 PTP 到位误差约 0.1 mm。第三次回车后脚本先检查出已有 ESTOP，此时还未发送启用混合控制的命令。

保留的 native 故障状态显示 QP1 为 `primal_infeasible`、QP2 未运行，求解 2.33 ms。J4 实测约 134.87°，超过在线有效位置上界 134.6889°（URDF 上界 2.356 rad 再减 0.3° 边距）。旧 PTP IK 只检查物理限位，离线复现选中 J4 约 134.83°；切回在线保持时，位置约束要求 J4 在一个 5 ms 周期内回到边距内，速度界变成 −0.6323 rad/s。

现 Cartesian PTP 的 SRS 候选在排序前使用控制器实际位置上下界和边距筛选，显式传入的 `q_target` 也需通过同样检查。该目标重新选解后 J4 约 131.05°，距有效上界约 3.64°。PTP 仍为关节 PTP，扫描脚本默认速度比例从 0.30 降为 0.10。

这是控制器侧的规划改动，需要重启窗口 A 才能加载。建议使用 `python -m peirastic.apps.run_controller --log-csv` 保留后续全过程日志。当前锁存按原有复位流程处理；不会因补丁自动续跑。详细证据见 [本次排查记录](../../../MD/phantom_ptp_publication_20260908.md)。
