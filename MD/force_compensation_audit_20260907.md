## 确定的代码问题

1. 旧 monitor 把当前 TCP 姿态当作 link_7 姿态投影重力。当前 gripper2 的安装转角约为 $[1.0,49.9,-88.7]^\circ$，不能忽略。修正为先逆变换 TCP→link_7；默认直接显示控制器发布的真实 TCP 补偿量，同时给出独立重算对照。
2. 旧 monitor 调用离线 `build_dataset(..., use_inertia=False)` 时仍含线加速度、角速度、角加速度的一阶矩项，而控制器默认只有重力与零偏补偿。修正为复用相同的在线 observer，独立重算默认只补偿重力和零偏。旧离线辨识 API 的历史语义保留。
3. 旧 monitor 显示 sensor/link_7 原点的六维量，控制器使用 TCP 原点的六维量。修正后 `--frame tcp/link7/sensor` 同时指定坐标轴与力矩原点，原始与补偿曲线使用同一个坐标系。
4. V2 在 link_7 拟合，但旧 observer 只做原始符号处理、用 sensor 重力回归。非同位传感器时两者不一致。修正为在 link_7 统一参数、重力和测量 wrench，并保持旧 sensor 参数文件兼容。当前传感器配置恰好同位，因此这项不是这次现场异常的直接证据。
5. `pooled_shrinkage_cov` 原先把不同姿态的样本直接混合估算噪声，将真实重力变化计入了噪声；campaign 还把留出窗口用于估计拟合权重。现改为逐静态窗口去中心、只用训练窗口估计协方差。

模型文件现在原子写入并记录参数坐标系、传感器/工具绑定。无穷大的动态诊断置信区间写为 JSON null，不阻止有效的静态标定保存；非法载荷参数仍拒绝。observer 提供显式维护重载方法，控制器不会在活动接触过程中自动更换模型。

TCP 原点的力矩残差会包含未补偿力经过力臂产生的项。这是物理 wrench 变换：

$$
F_T=R_{LT}^{\mathsf T}F_L,\qquad
\tau_T=R_{LT}^{\mathsf T}\left(\tau_L-r_{LT}\times F_L\right).
$$

旋转不会改变力向量模长；更换力矩原点会改变力矩模长。当前静态 CSV 中 TCP 的 $|M_y|$ 最大值为 $0.08841\,\mathrm{N\,m}$，$|M_z|$ 最大值为 $0.08828\,\mathrm{N\,m}$。

## 复现

在已安装项目依赖的 Python 环境、仓库根目录运行：

```bash
PYTHONPATH=rm75_control:. python rm75_control/apps/force_compensation/audit_payload.py \
  --log rm75_control/data/force_compensation/logs/payload_id_v2.csv \
  --phi rm75_control/data/force_compensation/logs/force_id_phi_v2.json \
  --refit
```

此命令只读 CSV/模型并输出 JSON，不发运动命令、不保存或推广标定。

monitor 默认显示控制器真实补偿量；`--recompute` 使用独立重力/零偏重算，`--frame sensor` 或 `--frame link7` 切换同原点/同坐标轴对照。`--phi`、`--phi-source` 和兼容选项 `--10p-only` 会选择独立重算，避免误以为已更换控制器的模型。动态运动时，控制器和低频 monitor 重算的采样/滤波差异会造成对照误差，应在静止无接触状态判断零偏。

数值回归覆盖：任意传感器旋转/平移、真实 gripper2 安装角、TCP 六个通道的正负输入、零外力多姿态、位置量化不制造惯性残差、旧参数换原点的动力学一致性、坏模型保留原值、诊断无穷大处理、噪声估计对窗口均值平移不变，以及留出窗口变化不能改变拟合参数。
