# Active 003：左侧缺失与 tilt 诊断

五条记录均成功保存，并以 `phase_complete` 结束。这次确实触发了 QP 新增修正，但其量很小；部分低质量时刻被力优先限制，另一些时刻名义压入已满足当前速度型修复策略。末尾还存在原图可见左侧缺失、窗口评分却高于阈值的情况。此次没有修改生产控制器、检测配置或力裕量。

## DtP 起点：已检测且已有修正，力优先经常阻止进一步压入

L DtP 扫描最初 5 s，约 70.96% 的拍左侧低于阈值；这些低质量拍中约 54.32% 的工具 Z 力高于 4.1 N。当前可靠误差符号带为 ±0.1 N，并非设备故障上限。

例如 control 1452（扫描开始后约 0.015 s）：左窗 0.660、力 4.102 N；视觉要求左局部压入速度约 0.350 mm/s，名义动作只有 0.255 mm/s，但 QP 基本没有新增法向/tilt，α 约 0.869。

按用户声明的 50 mm 孔径、中心 TCP 和当前几何，两端力优先行在 F>4.1 N 时要求：

`Δvn − 0.025 Δω ≤ 0` 且 `Δvn + 0.025 Δω ≤ 0`，即 `Δvn + 0.025 |Δω| ≤ 0`。

这使整个孔径内的新增局部压入均不能为正。它是当前接触中心不确定区间下的保守相对基线约束，不能理解为任何真实组织上的 rocking 都一定增大力，也不等同机器人硬安全极限。

修正不是等到扫描后半段才开始：control 1481（约 0.159 s）左窗 0.655、力 4.028 N，名义角速 −0.326°/s，QP 改成 −0.465°/s；control 1528（约 0.396 s）名义 −1.081°/s，QP 改成 −1.759°/s。当前映射下负 Y rocking 有助于左侧向内运动。只是这一段新增角速度指令累计量约 0.28°，难以肉眼看出持续的大幅 tilt。

## PtD 中后段：图像很差，但速度型策略可以由名义压入满足

L PtD 左窗低于阈值出现在扫描约 11.61–31.00 s 内；C PtD 约 11.68–22.64 s 内。这里的“末尾”应区分中后段缺失与最后几秒。

L PtD control 5641（约 22.783 s）是明确例子：

- 左窗质量 **0.416**，力 **3.640 N**；
- 名义法向速度 **4.453 mm/s**，名义 rocking **−0.842°/s**；
- 左声窗中心在 TCP +15.5 mm，故名义局部压入 `vn − 0.0155 ω` 约 **4.681 mm/s**；
- 当前图像策略只要求约 **0.961 mm/s**；
- 所以 QP 基本不追加 tilt，主要将 α 降到 **0.640**。

这是当前策略的实质局限：约束要求局部法向速度达到一个底线，并不要求左窗差时必须采用倾斜，也不验证同一动作是否真的改善图像。正常法向压入可以满足它；力已恢复、声窗却仍差时，也没有自动累积倾斜修复请求。满足速度不等于接触/声窗已经修复。C PtD 的 1,970 个低质量拍中，1,950 个已经由名义动作满足该速度请求，这解释了该段几乎看不到 QP 新增 tilt。

## PtD 最后几秒：当前评分漏掉了用户关心的部分黑带

见 [L PtD 原图、confidence 与逐列评分](visual/RH_Per_L_PtD.png)，第三行是保存图像结束前约 0.5 s：原图左侧仍有暗带，左窗评分却为 **0.9325**，高于 0.8。

当前评价取顶部 **22%** 深度，在左右各 **30%** 宽度窗口内做均值；最外侧约 **4%** 也不纳入窗口。较深缺失、窄黑带以及近场亮反射可能不使这个均值跌破阈值。该例连顶部左窗的逐列均值也全部高于 0.8，因此仅把横向均值换成最小值、仍只看这一浅层 ROI，未必能检出它。

这是当前评价目标/区域与用户所关心缺失之间的不匹配。15 个选中帧中 12 个有相同在线图像序号，重算质量误差全部为 0；未发现这些帧的在线提取计算不一致。黑色区域本身也不是物理未接触真值，不能把深部声影直接解释成应该继续压入。

C PtD 结束前 0.5 s 的选中帧左窗约 0.9985，未见同等明显左侧缺失；不应将所有 PtD 末尾一概判为同一问题。五条原图诊断均在 `visual/`，选帧数值在 `visual/metrics.json`。

## 后续修正应针对什么

这批数据暴露的是三件不同的事：缺失评价范围不完整、速度型修复可以被名义压入提前满足，以及零新增力恶化约束限制了可用 rocking。单独增加 tilt 增益不能同时解决它们。

下一版应先用这些原图冻结可观察缺失区域的评价规则；再针对“低质量持续、实测动作没有带来改善”的片段设计有界修复请求，使是否继续修复依据图像响应，而非仅依据名义速度底线。是否允许额外力裕量属于另一个明确的策略选择，本轮未更改。诊断不能代替下一版闭环效果验收。

## 独立 ultra 五点复算

对 controls 1452 / 1528（L DtP）以及 5641 / 5791 / 7288（L PtD）做单状态回放，原设置下输出与记录的 candidate 逐元素一致（最大绝对差 0）。成功日志未保存精确 solver 时刻和 measured_angle：回放采用日志时刻，所选图像均远离过期边界；角度取 0 并重复 ±0.3 rad，结果相同，原角限为 150°。因此并非恢复了所有未记录内部状态。离线去除约束的比较仅解释数学限制，不是新控制器闭环试验，也没有发布任何动作。

- 1452：两端力优先行绑定。仅离线移除力优先后，才出现额外法向 +0.0551 mm/s、rocking −0.0890°/s；移除孔径附加项不能解决该点。
- 1528：本来就有新增 rocking −0.6777°/s，孔径预算绑定。去掉孔径附加预算和代价后，可增到约 −0.7154°/s，随后受命令 slew 限制；不能假设仅去掉孔径就能无限倾斜。
- 5641：名义左局部速度 4.6807 mm/s 已超过请求 0.9611 mm/s，去掉力优先或孔径均不会产生实质新增 tilt。这是速度策略满足条件的问题。
- 5791：已新增 −0.6121°/s，左局部速度仍低于请求，正松弛体现软任务折中；不能把正松弛当成物理不可修复证明。
- 7288：末尾评分 0.82769>0.8，各版本均沿用名义动作，α=1，说明该点不追加动作来自检测/策略请求，而不是孔径或力方向约束挡住修复。

复算产物在项目根目录 `analysis_artifacts/active003_qp_review/five_state_replay.json`。这些结果支持上述诊断，不构成声学收敛证明。
