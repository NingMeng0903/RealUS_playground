# 控制器 QPIK OUT、观察窗口干扰与轨道联动修复

对照基线：`8d427fca476191226656ba24e2c61c6f2fae877f`。检查对象为当前工作区（HEAD `05f3382c` 加原有未提交修改），修复未提交到 Git。native 已重新编译，协议升级到 v8；重新启动控制器、ForceMonitor 和 Genesis 窗口后加载新代码。

**为什么会停机**

现场日志有两条不同的故障链：求解/调度拖延导致 native 请求超时，以及 QP1 没有产出满足硬约束的解。现有 QPIK OUT/停止保护会拦截这两类情况。日志写入函数自身耗时小，不代表后台 CSV 格式化线程没有通过 Python GIL 干扰控制线程。

| 现场 CSV | 行数 | 有效证据 |
|---|---:|---|
| `run_20260907_210959.csv` | 5710 | QP2 P99 5.44 ms、最大 13.94 ms；17 拍 timeout coast 后出现 native timeout 停止 |
| `run_20260907_211243.csv` | 4259 | 3851 拍 timeout coast，只有 408 拍有完成的解；QP2 最大 367.16 ms |
| `run_20260907_211315.csv` | 941 | QP1 最大 57.83 ms；59 拍 timeout coast |

5 ms 周期下，几百毫秒的 QP2 本身就足以解释卡顿。无限 coast 的改法只会把停机变成长期保持旧位置。coast 行的零值不能当作实际求解耗时。逐阶段统计见 [原始日志分析](controller_timing_20260907.json)。

**已修正的具体问题**

- native 只限制外层迭代，ProxQP 内层默认仍可能运行 1500 次；现在两层均有上限，内层为 32。恢复每次 QP 数据更新的预条件处理，并清理失败解的热启动状态。
- 新版根据剩余墙钟预算估算迭代次数。前段计算或系统抢占耗尽预算后，强制 QP1 只跑一次，随后硬约束认证失败。现在 QP1 保留配置的有界迭代预算，剩余时间不足只跳过可选 QP2。专门的预算耗尽测试确认 QP1 能继续迭代并通过认证。
- 删除去掉 CBF 后重试、把未认证制动命令标成 solved 的退路。QP2 失败可使用已认证的 QP1；真实不可行仍停止。
- native 通知改为非阻塞，SHM 序号为完成依据。短暂等待期间保持位置并冻结轨迹时间；同一请求按实际年龄判断，不反复累计为多个超时。请求超过 50 ms 或 native 退出仍锁存停止。等待期间禁止提交尚未完成的 SHM 候选结果。
- CSV 格式化、JSON 编码和文件写入移到独立低优先级进程。控制侧仅复制必要快照并尝试入队，容量 80；队列满、文件失败或写入进程失效只丢日志。关闭有界等待。恢复记录 coast 行，保留故障证据。
- 状态转发不再在 SDK UDP 回调中做 FK、力处理和 SHM 发布；单独线程读取最新缓存，使用独立 Pinocchio Model/Data，删除重复 watchdog/轨道发布线程。
- ForceMonitor、Genesis 和日志进程限制数值库线程数并降低进程优先级。默认 `control_cpu`/`native_cpu` 均为空，关闭默认 C-state 锁定，没有自动相邻 CPU 绑定或自动 native FIFO 设置。
- 轨道 PTP 速度切回 tracking 上限时，旧加速度可能把下一拍 jerk/加速度上下界推成空集。现在只在构造下一拍边界时限制旧加速度，实际执行导数仍如实记录。停止、复位和重新使能清理旧 reservation，提交时在锁内复查运行状态。
- 本地编译任务首次应用会话 DOF 时，明确应用 7/8 轴状态，修复“推断为 8 轴，所以跳过设置”导致旧 HOLD 锁残留的问题；显式 7 轴会话仍锁轨道。

**碰撞体与 CBF**

默认碰撞模型恢复为基线使用的 `RM75-6F-8dof.collision.urdf` STL 网格。此前名为 capsule 的模型实际使用较粗的圆柱包络；在 15 个选取的现场姿态中，50 mm 激活范围内，网格有 1–2 对、包络有 5–6 对。一个实例中 `link_6/link_8` 从网格的 40.008 mm 变为包络的 8.206 mm，低于 10 mm 安全距离，改变了控制问题的可行性。

native 为网格增加保守的 AABB 包围球粗筛；不能可靠计算包围球时仍回退到精确查询。没有降低安全距离。测试将三个现场姿态的 native 激活对数与 Python 全对精确距离查询逐一比较。各姿态、额外激活对和距离见 [碰撞模型审计](controller_collision_audit_20260907.json)。
