# V15 通用 β 解剖 Retarget 完整执行计划 — 2026-09-08

## 2026-09-09 执行优先级修订（用户最新要求）

交付目标是同一通用算法接收新 β，自动编译一次，之后由 θ 驱动。采集编号只用于验证数据索引；算法不得根据编号、某个 β 的数值或某个动作选择专用修补。

当前先解决会直接破坏整体外观和联动的错误：屈腿时股骨大范围顶出膝部、足骨方向及位置错位、成片动静脉/神经/其他软组织穿出皮肤，以及明显脱开的关节。允许按真实多视角图审接受肘部等位置的小范围合理骨突出。毫米级内脏接触优化暂不占用主线；保留测量和失败记录，后续处理。

验收首先看 Genesis 全身、屈腿、髋膝踝局部与连续动作，并用每个 mesh 出皮的分布、面积/顶点比例、位置和持续性辅助判断。下面的精细接触/体积容差继续作为诊断目标，不将单个细小接触误差等同于整个通用算法不可用，也不以总体大致合理豁免股骨顶出膝盖或大范围血管出皮。

执行顺序调整为：通用下肢 rest/bind/运动一致性 → 原权重共同运输全部组织 → 两个采集 β 与固定生成 β 上的同规则动作验证 → 对明显残余问题继续修正。现有 V16 内脏局部试验收尾保存，不继续针对两份采集体型反复微调器官。

本计划替换上一版“六体型验证”计划。六体型只作为回归样本，产品目标是任意新 β 均可进入同一自动编译流程，无须针对该体型人工改参数或代码。计划最初只记录目标；后续已实施双侧锁骨响应修正及独立复测，但尚未完成下述通用编译器。实施状态见[本轮修改与真实图审](anatomy_v15_execution_review_20260908.md)。

## 1. 目标、约束与当前事实

运行语义沿用已接受的方案：每个新 β 自动编译一次，之后以 θ 和 transl 连续驱动。相同 β、源资产和配置可复用缓存；更换 β 自动重新编译。当前模型合同为冻结男性 SMPL-X 的 10 维 β 与 55×3 轴角 θ。维度严格验证，不静默忽略额外系数。

“任意 β”表示不设体型名单、不以距离两份采集或六个样本的远近决定支持、不裁剪 β。几何有效并满足约束的未见 β，应由同一算法自动处理。它不等于任意无限大系数都必然产生可用人体：目标皮肤无效、骨端/截面保护与可用空间矛盾等情况必须报告。未收敛与已证明的几何不可行分开记录。

保留 142 的原拓扑、235 控制器、逐顶点权重、父子结构和辅助联动结构。允许独立骨组件目标及骨骼/软组织共享修正场，允许离线校准辅助响应数值。骨干轴向总长度调整仍遵守已接受的 ±10% 限制，骨端和截面粗细保留；不能为某个 β 偷偷缩细骨头或扩大长度限制。

骨骼轻微出皮由多视角图审按区域判断，没有统一骨骼皮外上限。关节接合、骨端形状和联动优先；血管与软组织继续接受皮内、管径、分叉和穿入检查。

当前证据（双侧修正后）：两个采集体型分别完成 T-pose、两采集动作与六段日常动作首/中/末帧，共 42 次同输入比较，均可求值，原权重和拓扑一致。双侧锁骨响应已覆盖完整手部子树；Genesis 对照可见 AMASS 动作中的右臂及相连血管位置改善，采集动作变化很小。血管最大出皮仍达到 213328 的 38.966 mm、213712 的 29.930 mm，骨端接合尚未通过。桡尺骨原有相交和混合权重导致的动作骨端形变仍存在。独立骨组件目标模块已有实现及测试，但尚未接入生产 pose，也没有完成共享软组织场。尚无全身解剖通过候选。

代码上，V14 compile_subject 主要是组装器；V8 下游存在 |β_i|≤3 的人工限制，vertices/rest joints/bind twists 使用冻结线性基底。删除范围常数不能使该基底具备任意 β 的几何有效性。

## 2. 通用编译与联动修正

### A. 固定源资产，分离旧线性体型路径

- 142 是唯一原 rig/权重与联动来源；V7 提供对照及初始化线索，V14 提供运行、验证和保存回放基础。
- V15 新建独立编译合同，不通过修改 V8/V14 的保存语义扩大其 β 域。旧包继续精确回放。
- 从输入 β 直接计算冻结 SMPL-X 模型的实际 rest skin 和 joints；不使用其他体型的缓存皮肤，不把旧 anatomy beta_vertex_basis 当最终骨形或任意 β 的有效性证明。
- 原始运动参考、β 对应的目标绑定、独立骨组件帧分别保存。235 控制器的 β 相关帧通过目标关节与源 rig 语义生成；目标 rest 变动不能被 coupling 的重建抵消。

### B. 将完整自动求解接入 compile_subject

- 不允许 subject ID 分支、为某个 β 写死的世界坐标、人工选择某个历史候选或邻近 β 套包。
- 由当前 β 的皮肤、关节和骨面标定自动生成关节站点、局部轴、可用空间及初始骨布局。几何目标按局部尺寸归一化，验收毫米容差保持一致。
- 使用确定性初始化、受约束求解和自适应步长延续。延续路径失败时尝试预定多初值，不能把路径失败或优化预算耗尽直接判成目标 β 不可行。
- 每个新 β 都重新完成必要的骨层、材料场、动作校正和验证；可缓存相同输入的结果，但不能跳过几何检查。

### C. 先修双侧骨链，再修独立骨组件

- 将左锁骨修复推广为左右明确配置，核查锁骨—肩—肘—腕—全部手指的运动原点与轴；随后处理双侧髋—膝—踝—足。
- rest 骨位置与 global/local/inverse bind 由一致结果生成，手足始终随完整父链运动，禁止独立世界空间覆盖。
- 桡骨和尺骨分别求解近端、远端及相邻骨面的关系；不能继续靠共同搬动消除它们原有的交叉。
- 骨干使用保端轴向变形，轴向长度来自解剖标定，不将网格最大跨度直接除以 SMPL-X 两关节间距。
- 每个骨组件保存经过体型适配的 rest 形状与固定姿态运动规则。其骨面目标减去原 LBS 输出形成完整残差，恢复动作中的骨端刚性；事后刚体旋转已经压扁的骨端不能完成此修复。
- 髋球窝、膝髁—胫骨平台、肱骨—尺桡骨、腕踝接合使用双方骨面区域、方向和覆盖率。真实接合与仅需排斥的骨对分别声明，不能把所有相邻骨都强行拉成接触。

### D. 原始穿插修复与共享组织场

- 先离线修复原始骨间关系及受影响软组织的位置，保留网格连接和血管分叉，再冻结材料坐标。同一个可逆场不能消除输入中已经存在的骨—骨或骨—管相交。
- 为每个 β 建立覆盖骨、皮肤和全部组织查询点的 ambient 四面体体积网格，避免沿用只适合参考体型的 cage 范围。
- 骨组件提供精确目标；皮肤只对软组织施加内侧距离约束。允许图审认可的出皮骨段留在 ambient 域中，避免相互矛盾的骨/皮边界条件。
- 全部软组织顶点保存固定 tet ID 与重心坐标；禁止按整条血管 mesh owner 筛选，禁止运行时最近点重绑定。
- 复用已有 FEM、稀疏求解和防翻转工具；不继承旧路径的 24 点最近节点合并、50/50 混合、cage 外冻结或最近边界回退。
- 分开保存精确骨边界项和可压缩内域项。检查总变形、实际组织表面和压缩误差，不能只检查残差场自身的 Jacobian。

### E. 通用 θ 校正与固定运行包

- 每个 β 使用同一组规则和目标生成姿态拟合问题，无须人工为该体型挑选动作或调整响应。
- 拟合包括两个采集动作、规则姿态扫描，以及肩肘、肘屈伸/前臂扭转、髋膝踝等相邻关节组合。源辅助结构和联动保留，具体响应数值允许离线校准。
- 局部关节旋转矩阵作为特征，骨组件修正与软组织残差编译为固定 RBF/降维系数。手指与足部作为完整子树覆盖。
- 运行只计算原 235 控制器响应、原权重 LBS、精确骨组件残差和固定共享组织场；不访问 Blender，不解 PDE，不逐帧优化或重新绑定。
- θ 支持由每个包的拟合覆盖和实际验证记录决定；计算半径不能冒充解剖活动范围，超域不裁角。

## 3. β × θ 验证、图审与验收

### β 覆盖

- 固定回归：213328、213712、β=0，以及全部 10 个坐标轴分别 ±1.5 的 20 个体型。原先四个高/矮/宽厚变化样本包含在其中。
- 开发组合覆盖：10 维 scrambled Sobol 的 32 个点，seed=20260908，映射到 [-2,2]^10。
- 独立组合验证：另 32 个点，seed=20260909，同样映射到 [-2,2]^10；在算法及配置冻结后评估，不能根据其结果增加特定 β 分支。
- 边界压力：全部 10 个轴分别 ±3.1，确认 V15 没有继续触发旧 ±3 人工拒绝；是否可用由真实几何和约束决定，不要求极端输入无条件通过。
- 上述数值范围仅定义测试覆盖，不构成运行输入域或体型白名单。每个输入都记录成功、未收敛、无效几何或已确认约束冲突，不能只汇报成功样本。
- 对接近翻转、接合或组织空间阈值的开发 β 区间自适应细分；新增点作为开发数据，保持独立验证身份清楚。
- 对相邻 β 的 rest 骨面、绑定、组件帧和材料坐标输出做连续性检查，发现优化分支跳变必须修复或标记未解决。

### 验收与真实图像

- 骨端与截面形状误差目标 ≤0.1 mm，分别检查体型适配后及动作中。
- 软组织最大皮外距离目标 ≤1 mm；骨—骨、管—骨穿入 >0.5 mm 失败。
- 完整三角面相交、双向距离、骨面接合覆盖率和方向同时检查。采样深度只作为下界，无效或不确定测量不能计为通过。
- 检查总场翻转、实际组织自交、管径分布、分叉连续性及帧间跳变。原模型已有问题不自动豁免。
- 骨骼出皮单独记录最大值、分布、面积、位置与持续时间，由主 agent 和独立 agent按 Genesis 多视角判断；不再作为统一毫米硬门槛。
- 每阶段输出实际 Genesis 全身和双侧髋、膝、肘、腕踝图。连续窗口数值检查使用原始帧；视频按时间抽帧，并额外保存所有最差帧对应局部图。
- 阶段推进以关节与骨层先通过为准，然后完成组织场与联合复测。少数局部通过不能发布为全身通过。

## 4. 接口、保存和失败行为

```python
compiled = compile_subject(betas, source, config)
vertices = pose(compiled, pose55, transl)
```

V15 compile_subject 是完整自动适配入口；V14 组装器保留为旧版本内部能力。调用方提供新 β 即可，不需要提供预先人工拟合的位移、roll 或该体型专用参数。

包内保存原始权重/拓扑/235 层级、目标 rest/bind、独立骨组件、固定材料坐标、姿态场和组织场系数、误差及图审记录。缓存键包含实际 β、SMPL-X 模型、源资产、配置与算法版本哈希；不对 β 分箱，也不采用最近体型的包替代。

保存原始采集 NPZ 路径与 SHA256；非采集 β 保存精确输入及生成协议。分别报告输入有效性、求解收敛、约束检查、动作覆盖、图审和最终可用状态。保留失败诊断包，但不将其作为已通过 anatomy 包交付。

接口不裁剪 β/θ、不静默忽略维度、不因超出参考 cage 使用最近点补救。数值输入有效但无法完成几何求解时，明确指出失败部位和约束余量；只有明确证据支持时才称不可行。

## 5. 执行顺序与交付

1. 锁定源资产、模型及数据哈希；复算原始 142、V7 与 V14 对照，补齐 V15 β 合同和自动编译入口。
2. 完成双侧锁骨/上肢整链及独立骨组件，检查原始相交、手部继承与动作骨端刚性，再完成双侧下肢。
3. 对两采集 β 先验证完整自动流程，再运行全 10D 的轴向和组合 β 覆盖；阶段中禁止增加体型特例。
4. 构建每 β 的共享材料场并烘焙 θ 修正，完成独立 β × θ、真实 Genesis 图审和保存回放检查。
5. 交付通用编译器、直接驱动示例、两个采集和四个合成回归包、连续视频、完整测试输入/结果索引、可行性及支持范围报告。其他 β 验证按批次运行，保留输入、指标、哈希和必要图像，不复制所有临时几何；不删除既有历史资产。
