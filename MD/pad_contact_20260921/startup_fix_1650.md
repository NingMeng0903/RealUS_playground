## 本轮修复

- pad 候选命令覆盖原有的完整有效期：最早为上次发布后 20 ms，最晚仍受 50 ms 命令年龄及力/姿态反馈期限限制。移除旧 `dispatch_lead_s` / `dispatch_window_s`；旧独立配置会迁移到 `full_command_lifetime_v1`。
- 角速度、加速度、jerk 及角度约束覆盖从最早到最晚的全部发送时刻。jerk 二次边界包含内部极值；角度按实际可能的发布间隔约束。到 arm 调用边界再次检查时间，成功后仅提交一次。
- ultra 审查还复现了一个数值容差缺口：早期审查允许偏离完整区间 5e-6 rad/s 的 IK 结果，晚些在 jerk 极值处发送就会越界。现已按相同的 1e-8 容差审查完整角速度区间，并加入确定性回归；通用笛卡尔行容差不再替代这一检查。
- 为变化的计算时延保留制动余量。原速度/加速度/jerk 上限不增加；使用与未来窗口宽度无关的保守加速度界。默认参数下实际可用角加速度约 0.589 rad/s²，低于配置的 2 rad/s²。这是可行性余量，不是在线调整机械 M/D。
- 无接触、冻结或停滞时撤销视觉并暂停贴面请求，保留最终 jerk 约束要求的有限制动尾段。不会把高速旋转瞬间截为零，也不会用视觉绕过机械保护。
- 运行中切入 pad 时，继承上一条成功发布的“机械臂命令 + 导轨执行速度”模型，与最终审查使用同一模型。之前使用全部命令关节速度，导轨有跟随延迟时会制造不一致的初始平移历史。旧模式的接管方式不变；该问题不能从缺失首拍输入的 165023 日志单独证实。
- 记录 `pad_handoff` 和失败时的 `pad_allocation_failed`：包括前次命令、名义量、力/姿态、守护区间、发布区间及完整数值重放输入。真正过期、超力或不可行的命令仍停止。

以上只修改新手柄路径；021 YAML、共享扫描分配器和旧 record 的控制律未修改。角度边界、内层关节约束、反馈异常仍可能构成真实的不可行情况；本轮没有将保护失败改成继续发送。

```bash
bash /media/camp/EXT_DRIVE/RealUS_playground/scripts/run_icra_outer.sh confidence \
  --feature-config /media/camp/EXT_DRIVE/RealUS_playground/peirastic/config/contact_qp/pad_contact.yaml
```

该命令使用现有 genesis 环境、正确 PYTHONPATH 和单线程数值库。不要设置 `CONTACT_QP_CONFIG=pad_contact.yaml`，launcher 的扫描预检需要原扫描配置。端口 17361 只保留一个特征发布者；新协议为 `nearfield_column_echo_v1`，145 列，深度比例 `[0.04, 0.22]`。

控制器、手柄继续使用原来的启动命令；本轮没有更改 native 二进制，也未操作机器人。先在体模验证启动、接触和释放；真人弹跳及黑边恢复效果仍须闭环对照确认。
