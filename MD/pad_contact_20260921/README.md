# 手柄 UltraPoC 统一贴合：实现与离线验证

本次只让新 `pad_contact` 手柄路径使用统一分配。021 的配置、扫描执行器和旧 record 控制行为没有改动；原有显式 `pad_visual` 请求仍可用于历史对照。当前代码是待体模闭环验收的实现，不能将下列离线结果解释成真人弹跳已解决。

## 启动与配置

保留原命令：

```bash
bash run.sh gamepad --hybrid-law ultrapoc --analysis
```

新增 `--pad-contact-config /绝对路径/pad_contact.yaml`，默认配置为 `peirastic/config/contact_qp/pad_contact.yaml`。更新代码后应重启控制进程和超声特征进程。特征发布者需要发送 `nearfield_column_echo_v1`；旧进程只有 q 时，新模式会暂停平移、撤销视觉请求。独立特征进程入口为：

```bash
python -m peirastic.apps.contact_qp_features --feature-config peirastic/config/contact_qp/pad_contact.yaml
```

不要同时启动两个使用同一发布端口的特征进程。新路径要求已标定且重合的 tool/contact 坐标系、4 N / My*=0；配置不兼容会拒绝安装。

初始上限：Z 15 mm/s，视觉要求 0.10 rad/s，最终转动 0.28 rad/s、2 rad/s²；jerk 来自原机械 M/D，不乘视觉放大系数。黑边平移目标上限 10 mm/s，持续 0.5 s 后暂停，降速/恢复斜坡 0.12/0.30 s；恢复需新原始观测持续 0.25 s。图像超过 0.30 s 失效。4–4.5 N 逐渐撤销视觉要求。6 N 只监督、短时过冲继续回缩，持续 0.15 s 或达到 8 N 才停机。手柄与扫描李萨如共用 5 ms / 200 Hz 力环：力、COP 和图像融合按 5 ms 命令保持积分，导轨异步入队，不再等待 40 ms 确认，也不再额外等待 20 ms 发布间隔。

## 最终命令和事务

`PadContactOuter` 准备原机械名义 U/Ω，图像给最终 Ω 的软要求，不再相加。分配使用扫描共用数值模块，COP 软目标为 `(U-Um)-c*(Ω-Ωm)`。COP 无效时退回机械并降至暂停。

分配后的全部笛卡尔约束送入 Python/native IK。并行约束取交集压缩至最多 16 行，不放松 jerk。IK 后再检查速度、角度、实际发布间隔的加速度/jerk、机械保护、平移暂停和运动子空间。手柄释放、反向、滚转/偏航启动通过有限减速过渡处理；没有位置积分，没有补走请求。

状态仅在发送链完成后提交。机械法向记忆扣除 COP 几何补偿；最终 Ω 进入转动历史。命令时间以 dispatch admission 为准，成功后才写入历史；发送完成时间另存。这里是发布命令的运动学模型，不是实测 TCP 运动或设备精确生效时间。

手柄使用直接 arm SDK 的成功返回，并对导轨增加可选工作线程确认：同一命令序号的 drive 调用必须成功返回；量化/死区保留前一次设备命令会记录 `retained_device_command`，不是虚构一次新写入。软限位 hold、失去校准、反馈无效、停止、序号替换或超时均撤销事务并停止。无确认的 CANFD proxy 不支持此模式。旧 `commit_reservation()` 默认异步行为未变。

导轨入队成功即可，与扫描路径相同。内环和力环始终按 5 ms 命令保持积分，墙钟只作诊断。已发布一部分后失败只能停止并标记部分失败，软件不能撤回已送达设备的指令。

## 图像与日志

近场特征保留整个已注册声学孔径，使用每列 4%–22% 深度的 p75 显示灰度。q 仍保留，深部置信度降低不能单独产生转动。局部回声基线在稳定、无缺失时建立；缺失、失联或力波动时冻结。方向需要两个新帧支持；预测仅作趋势日志，不能完成修复或单独换向。均匀暗、双侧缺失及证据冲突暂停平移。

日志包装通过 `functools.wraps` 保留反馈参数签名。`pad_configuration` 保存生效配置、HEAD 和关键脏源码哈希；`pad_allocation` 保存原始/预测证据、COP、名义量、分配、视觉未满足量、约束和测量来源；`pad_publication_review/commit/abort` 保存最终命令、实际发送间隔审计和设备结果。`control_sample.v_cmd` 是外环分配量，不能用作实测速度；实测反馈另列。

本目录 `replay/` 保留两场 CSV/JSON。共提取 1978 / 1849 帧；力反馈仍按原始控制时间推进。旧日志没有帧号对应关系，因此接收时间明确建模为 capture+77 ms，加上已标定 151.964 ms 图像延迟，年龄约 228.964 ms；不是恢复出了旧控制器的逐帧输入。降到 10 Hz 会人为触发过期，不能用于正常帧率的参数评估。

按时间前半段/后半段分开统计，运行中未拟合参数。回放 JSON 中三个力稳定性参数当时为代码常量，之后移入 YAML，数值未变：相邻力变化 0.35 N、窗口 0.25 s、窗口范围 0.7 N。
