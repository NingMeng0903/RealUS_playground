# V13：逐顶点联动、真实动作与 Genesis 图审

本轮目标仍是每个体型离线 retarget 一次，随后用 SMPL-X 姿态参数驱动原 Blender 内部解剖，保留拓扑、辅助关节、骨端关系及相连组织。**当前材料附着候选未通过，不能作为完成版。** 用户已允许受限轴向调整，保留骨端形状与骨干粗细；本轮试验不能代表所有此类调整方案。

## 论文和版本依据

- [8 篇相关论文及适用边界](anatomy_literature_20260908.md)：Anatomy Transfer 的骨—皮边界体积映射、SKEL/OSSO/SKEL-J 的骨布局先验，以及 helper joint 权重转移。没有把皮肤权重转移论文当作内部血管无穿透证明。
- [独立 Git 代码审计](anatomy_git_audit_20260908.md)：逐项检查 `142ece5f`、`29e1072c`、V2/V5/V7/V8/V9/V10/V11/V12e。区分单次提交与提交区间差；`29e1072c` 自身两处修改不能单独证明“细骨”的首因。
- 已确认 V12e 的直接错误：整条 Artery/Vein 的 mesh owner 是 Head_Bone，按 owner 选前臂 follower 会漏掉具有实际前臂权重的管顶点。修复使用原 14-slot 逐顶点权重，避免对混合权重点反复硬搬运。

## 本轮实现与证据边界

1. `terminal_reseat_v12.py`：前臂软组织按真实 driver 权重共同搬运一次；采样种子改为稳定 SHA。骨网格仍使用保存的刚体 reseat。
2. `material_runtime_v13.py`：复用冻结 235 控制器及原权重；恢复已有骨校正；可保存固定材料映射并从姿态参数回放。运行不访问 Blender，也不做皮肤最近点或优化。**这只解决运行组织方式，不保证皮内包含或实时性能。**
3. `material_attachment_v13.py`：固定骨面三角形、重心坐标和完整局部偏移；在源已运动软组织上加目标骨与源骨的附着位置差。guided 版本结合原 driver 相似性选择骨面；这是工程假设，尚未实现骨—皮双边界体积场。
4. 独立代码审查发现并修复了负面索引、identity 旁路、序列化 dtype、材料映射与体型/顶点顺序未绑定的问题。原 rig 保存器会重建部分 bind 数组；新增精确数组保存，另做回放复验，原先非精确报告保留。

## 真实出图，而非仅日志

Genesis 入口复用仓库原有 `render_alignment_truth_genesis_v1._render_layer` 和 `GenesisPlatformRuntime`。新适配脚本只读取已保存的真实顶点，按骨/血管/神经分层；不重算 retarget。相机来自目标 SMPL-X joints 与 skin，源与候选采用相同相机及相同 root 逆旋转。

渲染目录：

- `outputs/anatomy_retarget/v13_genesis_review_20260908_002`：120°肘膝与未裁剪 AMASS 坐姿，每姿态修改前后各 13 个视角，保存 RGB/depth/segmentation。
- `outputs/anatomy_retarget/v13_genesis_review_20260908_003`：120°姿态的局部 depth slab，关节点前后各160mm，解决前景脚遮住膝的问题；全身视图保留完整场景。局部裁深不能单独证明无穿出。
- `outputs/anatomy_retarget/v13_sections_tpose_20260908_002`：三角形与真实截面的交线，作为3D图的补充。

主 agent 已实际打开并检查：Genesis 深屈全身、双肘局部、双膝局部、坐姿左足；双前臂与小腿截面。初版 PyVista 图把整数组织标签全部当 other，且相机过远，因此这些初版3D图**不能作为验收证据**。显式组织映射修复后的截面和 Genesis 图另外保存，没有重标旧图。

### 从图中得到的判断

- 坐姿左足：骨脚、相连血管和半透明皮肤脚明显错位，候选仍保留该失败。全身最大骨穿出位于左足小趾远节；213328为50.890mm，213712为47.542mm，不能误说成股骨或膝盖穿出。
- 深屈右肘：旧透明材质图曾呈现“候选血管更完整可见”。随后用上身顶点完全相同的station实验发现透明绘制本身会造成显隐伪差异，**撤回依据显隐推断联动改善的结论**。新图统一将骨、管、神经设为不透明，仅外皮透明；位移/穿骨结论以真实数组和修正后图复核。
- T-pose 左前臂截面：贴近皮外的一支红管被带入皮内。
- T-pose 右前臂截面：候选一段细长红管与金色骨轮廓相交。进一步对四根 watertight、winding-consistent 的 radius/ulna 单独计算 signed distance，确认新候选增加了部分管/神经入骨点；因此 **仅骨面附着候选拒绝**。
- 膝部第一版侧视被前景足遮挡，不能据此评判骨窝与骨端接触；调整裁深后另存003，仍需关节接触量共同判断。

## 完整矩阵与保存回放

四体型共44个cell均已完成，没有运行错误或未支持姿态；组织包含与管边长诊断通过数为0/44。全矩阵最大骨皮外距离56.822mm、最大血管皮外距离51.397mm。五个AMASS帧的支持不等于连续动作或任意角度支持。

初次矩阵保存重载并非bitexact（最大约1.19e-7m）。确认原保存器在float32上重新构造source/target global bind及inverse bind，新增source数组精确覆盖后，另存 `outputs/anatomy_retarget/v13_exact_replay_20260908_001`。四体型各两个held-out姿态、两种材料模式，共16个保存重载检查均逐位相同，而且与原矩阵保存的几何也逐位相同；没有靠放宽epsilon通过。这个检查只确认序列化保真，不改变几何拒绝结论。

局部相关测试32项通过。全394770顶点的当前NumPy参考运行在其他评估进程并行时约2.8秒/帧，不能称为实时实现；材料附着编译本身约12–17秒，完整离线body fit与评估耗时另计。

## 多姿态结果不能只报平均改善

主矩阵 `outputs/anatomy_retarget/v13_material_20260908_001` 包含两个采集 beta、两个明确合成 beta，T-pose、两个采集姿态、三个深屈姿态和五个固定 AMASS 姿态。AMASS 的 body/root/hand 旋转保留到float32，未进行75°裁角；SMPL-H betas没有移植到SMPL-X。合成体型使用 fresh V1 → anchored V11，应按其来源解释，不能冒充既有V12e优化候选。

已完成的采集体型示例，表内为血管最大皮外距离；骨几何在这三种材料对照中相同。

| 体型/姿态 | V12e 原结果 | 仅共享权重校正 | guided 骨面材料附着 |
|---|---:|---:|---:|
| 213328 / T-pose | 5.02mm | 14.53mm | 4.98mm |
| 213328 / 采集213328姿态 | 19.52mm | 13.52mm | 13.26mm |
| 213328 / 120°肘膝 | 13.05mm | 22.25mm | 11.29mm |
| 213328 / AMASS坐姿 | 45.69mm | 45.69mm | 45.68mm |
| 213712 / 120°肘膝 | 13.30mm | 19.98mm | 9.04mm |

因此，单纯“把原权重搬一次”有明确回退；guided 附着虽改善部分血管皮外距离，却增加局部穿骨，管边长比也仍失败。拓扑的 faces 不变不等于管径、形状与无相交成立。

## 轴向与足部假设

- 共同膝站位场测试0/10/20/30/35mm：同时搬动股骨远端、胫骨近端和髌骨，骨干中间平滑过渡，更新相关 bind；不作径向缩放。两采集体型各五个姿态中，所用穿出评分均选择0mm。当前试验不能接受，也不代表“所有受限骨干轴向调整均不可行”。
- 它包含膝站位移动与胫骨中心线变化，不等价于只缩短股骨而膝站位不变。报告必须保留此区别，不能拿“保粗细”掩盖错误的膝位置。
- 足部仅恢复target FK的独立消融也已拒绝：采集213328姿态的左足最大外露17.347→12.593mm，但未参与拟合的坐姿50.890→52.274mm；kicking与屈膝踝站位也有回退。手保持完全相同、小腿基本不变，局部改善不足以接受。见 `v13_foot_fk_20260908_001/report.json`。

## 尚未完成的必要工作

### 两个采集体型的专项 Genesis 复核

实际使用输入为仓库的 `smplx_outputs/20260713_213328/moment_0000/smplx_result.npz` 和 `smplx_outputs/20260713_213712/moment_0000/smplx_result.npz`。已核对编号与 SHA256；在 Among_US 的 NPZ 路径检索中没有发现同编号副本。外皮按各自 betas 重建，分别生成零姿态 T-pose、采集动作213328、采集动作213712，共六个 cell。此处没有把两个编号假定为两个不同的人。

完整修正材质的 [Genesis 浏览页](../outputs/anatomy_retarget/v13_capture_genesis_review_20260908_001/index.html) 提供体型、姿态、部位选择。每个 cell 有18个视角、SMPL-X外皮/V12e/V13三层，共324张真实 RGB，并保存 depth 与 segmentation。骨、血管和神经不透明，只有解剖视图中的外皮透明。旧 alpha=0.92 的内部组织图不再用于判断组织显隐改善。

主 agent 和独立 agent 均实际查看两个体型的 T-pose 与自身采集姿态的外皮、骨盆、髋、肘、膝局部图。外皮未见明显整体重建断裂，但这不是对原始相机观测拟合精度的认证；左肘的骨端偏置在局部图中可见，髋部受遮挡，单幅投影不能证明球窝接触。局部相机前后各160mm裁深，平整骨干切口不能误报为骨折。

原 NPZ 保存的 skin vertices 与当前重建外皮在去除整体平移后，213328 的 RMS/max 差为0.0378/0.3273mm，213712为0.0422/0.3568mm。原采集的根旋转/平移采用 EasyMocap 约定，不能简单将 Th 加到本地骨盆旋转后的网格上；所有内部检查都在皮肤和解剖共用坐标系中完成。具体见 `v13_capture_joint_geometry_20260908_001/stored_skin_crosscheck.json`。

骨面审查进一步区分原始缺陷和映射回退，见 [关节测量与因果审查](anatomy_capture_joint_audit_20260908.md)。查询是冻结局部关节域顶点到对侧完整闭合骨三角面的距离，不能把宽域的最大 unsigned 距离解释为关节间隙。

- 213328 自身采集动作：左肱骨关节域到桡骨的 closest/p05 从 raw 的0.147/3.818mm变为候选的12.890/19.084mm；到尺骨从0.113/0.802mm变为2.542/8.424mm。左肘存在明确新增分离。
- 两体型髋股骨头域的负 signed 点数与深度在 raw/candidate 总体接近，部分入骨关系原来已有，不能归因于材料附着新造成严重髋穿入。球心误差约2.4–3.3mm仍不足以证明接触正确。
- 213328 自身动作左膝内髁查询 raw 已出现13.188mm入骨，候选为12.902mm；两个体型的膝局部仍不合格，不能只把外皮含住或轴心接近当作通过。

本段的“完成”指数据导出、真实渲染和审查完成，不代表解剖候选通过。

### 左肘的阶段定位与保支点消融

进一步比较同一213328体型、同一V10运动下的V11和V12e。T-pose左肱骨域到桡骨的closest/p05从0.470/5.081mm变为8.654/17.416mm；自身采集动作从6.930/11.432mm变为12.890/19.084mm。因此V11在动作中已有部分分离，V12e又加重，不能把全部问题归给单一步骤。V12e桡/尺骨刚体搬移使V11材料肘心分别偏移20.502/22.774mm；bind不变并没有锁住实际骨端。独立测量见 `v13_elbow_stage_audit_20260908_001`，实际Genesis对照见 `v13_elbow_stage_genesis_20260908_001`（左V11、右V12e）。

新保支点试验使用V11冻结肱/桡/尺骨肘部材料域的中心，将左桡骨、尺骨作为同一个刚体，identity为起点，总旋转向量各分量限定在±5°，禁止额外平移、缩放、弯曲；沿用V12e的B_final与helper响应。27个组合用T-pose和两采集动作评分，坐下/踢腿序列帧独立验证。最优组合为[0,0,5]°，约163秒完成。

主agent实际打开 `v13_forearm_lock_genesis_20260908_001` 的采集左肘侧视、sitting肘正视与全身、kicking肘侧视。采集姿态的骨端投影关系改善，但不能补偿表中的T-pose、另一采集动作及held-out回退，因此拒绝。此消融只改变骨rest，软组织没有随这次额外旋转运输，不能把红管看起来仍在附近解释为联动通过；骨实验已失败，不进入软组织编译。新图共4姿态×3视角×2方案=24张RGB，另有depth/segmentation。

独立agent逐图复核后，又确认5个NPZ中仅893个骨顶点变化，血管/神经/其他软组织均source→candidate逐位相同。另一个agent对真实三角骨面复测：自身采集动作肱骨→桡骨closest/p05虽然从12.890/19.084mm下降到6.866/11.502mm，仍有分离；T-pose、sitting、kicking各新增2个负signed查询点。见 `v13_elbow_joint_lock_audit_20260908_001`。最终 `decision.json` 明确 `operational_evaluation_completed=true`、`anatomical_passed=false`、`rejected=true`，不存在以运行成功代替解剖通过。

当前没有可接受的最终 retarget 资产。骨端/关节位置与皮内可用空间要共同求解；软组织需要同时考虑骨边界、皮边界和管的连续形状，不能只用最近骨面位移。之后还需连续动作序列、更多体型、完整管自交/组织相交与性能验证。

冻结控制器响应本身有支持域：当前膝到130°、踝到75°，超域会拒绝；无法宣称“任何动作”已经成立。一次保存与回放通过也不构成解剖正确证明。所有本轮工件 `publishable=false`。
